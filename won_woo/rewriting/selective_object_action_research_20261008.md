# 원문별 최소 Object/Action 치환 연구 설계

작성일: 2026-10-08. 상태: 논문·코드·현재 데이터 확인을 바탕으로 작성한 실험 설계이며, 선택 알고리즘 구현이나 학습 결과는 아니다.

연구 질문은 **같은 사건을 설명하는 원문에서, 어떤 Object/Action의 어떤 등장 위치를 바꾸는 것이 실제로 필요한가**이다. 모든 표현에 동일한 치환을 적용하는 대신, 의미가 보존되는 후보 중 검색과 학습에 기여하는 작은 집합을 선택한다. 우선 목표는 Train 캡션의 선택적 증강과 원래 쿼리의 검색 성능 개선으로 둔다. 추론 시 여러 쿼리를 결합하는 실험은 별도로 평가한다.

## 1. MQVR에서 가져오는 내용과 새로 제안하는 내용

ECCV 2022 [Multi-Query Video Retrieval](https://arxiv.org/pdf/2201.03639)의 §3.2, Eq. (3)은 쿼리별 similarity를 평균하는 SA를 정의한다. MF와 가중 특징 결합도 실험하며, TS-WF는 쿼리 사이의 중복성을 고려한다. §4.2에서는 영상별 캡션을 무작위로 표집한다.

`source_caption_id`별 사건 유지, 원문 필수 포함, 추가 후보 0·1·2개 선택, 정답–최대 오답 margin 최적화, `원문+A+B`와 `원문+A+A` 비교는 이 논문의 방법으로 확인되지 않았다. **이 문서에서 제안하는 선택 방법**으로 구분한다. MQVR의 별도 주석 캡션과 동일 사건의 유의어 치환은 정보 중복 정도도 다르다.

## 2. 현재 데이터에서 먼저 해결할 사항

- 입력 후보: `diagram_synonym_pairs_final_20261007/additional_captions_rank1/`. 검증 보고서상 추가 쿼리는 Object 185,934개, Action 180,510개, 합계 366,444개이다. 연결 CSV를 포함해 원문별 생성 관계가 보존되어 있다.
- 현재 rank 1은 원래 CSV 순위이며, 보고서의 순위 기준은 표현의 알파벳 순서이다. 문맥·검색 품질의 1순위를 의미하지 않는다. 우선 기존 1순위 후보를 사용하고, 부적합하면 해당 위치를 유지한다. 다른 순위 탐색은 별도 실험으로 구분한다.
- 현재 생성은 실제 등장 위치의 품사와 의미를 검사하지 않았다. 첫 원문 `Phoebe picks up a drink from the bar.`에서 `picks → choices`, `picks → blames`, `bar → cake` 등이 만들어졌다. 문법·동작·장소 의미가 달라져 제외해야 한다. `drink → beverage`는 의미 검토에 통과할 수 있는 예이지만, 필요한 치환인지는 별도로 평가한다.
- 기존 생성은 `val_expression`이 아니라 `replacement_expression`을 썼다. Val에 실제 등장하는 표면형으로 옮기는 실험이라면, 선택된 1순위 관계의 실제 `val_expression`으로 후보를 다시 구성해야 한다. 연결된 여러 `mapping_id`의 Val 표면형이 다르면, 원래 rank1의 최초 데이터 행에 대응하는 대표 표면형 하나를 고정해 기존 후보 한 개 설정을 유지한다. 이 표면형으로 시제·수·구문을 보존할 수 없으면 치환하지 않는다. 새 굴절형을 임의로 만들지 않는다.
- 현재 사전은 Train ID만 포함한다. Val 어휘도 기존 사전의 같은 Object/Action·표면형·품사 범위로 제한해서 추출했다. 따라서 이 범위에서 C가 비어 있다는 결과를 전체 Val의 미지 어휘 부재로 해석하지 않는다. 연구 주장은 우선 **사전에 허용된 어휘의 문맥·노출과 검색 효과**에 한정한다.

선택의 기본 키는 `(source_caption_id, source_span_start, source_span_end, term_type)`이다. 같은 철자라도 문장 속 품사와 의미가 달라지면 별도 판단한다. 영상 ID만으로 묶지 않는다. 중복 생성 쿼리는 여러 원문에 연결될 수 있으므로 main CSV의 대표 source만 사용하지 않고 `links/generation_links_*.csv`의 모든 연결을 사용한다.

## 3. 후보 유효성 확인: 검색 점수보다 먼저

LLM으로 캡션을 생성하거나 판정하지 않는다. 기존 사전·WordNet 후보 관계와 실제 등장 위치를 확인하는 로컬 분석, 구문 규칙, 필요한 표본의 사람 검토를 사용한다.

확인 대상은 실제 위치의 Object/Action 역할, 해당 문맥의 단어 의미, 다단어 동작 전체, 행위자·대상·장소, 시제·부정·순서, 원래 사건의 시각적 의미다. 특히 `picks up`처럼 동사와 particle이 함께 뜻을 만드는 구문을 단일 단어의 다른 WordNet sense로 대치하지 않는다. 같은 synset에 포함된다는 사실만으로 문맥상 유효하다고 판단하지 않는다.

영상 전체의 정답 점수만으로 원래 사건 보존을 검증할 수 없다. 다른 사건을 설명해도 같은 영상이 정답일 수 있기 때문이다. 원문 timestamp가 있으면 같은 구간의 시각적 정합성을 확인하고, timestamp 미확정 후보는 상태를 유지해 별도 검토한다. 텍스트 검사·구간 점수만으로 확정하기 어려운 후보는 보류하며, 의미 보존을 입증한 것으로 표시하지 않는다.

길이와 실제 인코더의 truncation 여부도 후보별로 기록한다. 앞서 요청한 무필터 생성본은 그대로 보관한다. 14–20단어·30 미만 subword 조건의 적용 여부는 별도 실험 설정으로 명시하고, 그 조건을 사용하면 새 후보에 적용한다. 원문 길이를 맞추려고 원문을 임의로 늘리거나 줄이지 않는다. 현재 특징 추출의 최대 길이 30에는 특수 토큰이 포함되므로 단순 단어 수와 구분한다.

## 4. 원문마다 추가 쿼리 0·1·2개 선택

고정한 Holmes checkpoint로 원문과 유효 후보의 같은 영상 집합에 대한 점수를 계산한다. clip/frame 결합 계수와 영상 순서는 모든 비교에서 동일하게 둔다. 기존 `Holmes/Rewriter/evaluate.py`의 점수 계산을 재사용할 수 있다.

원문을 q, 유효 후보를 C(q), 선택할 추가 후보를 S라고 하면:

\[
Q=\{q\}\cup S,\quad |S|\leq2,\qquad
s_Q(v)=\frac{1}{|Q|}\sum_{r\in Q}s(r,v)
\]

\[
M(Q)=s_Q(v^+)-\max_{v\neq v^+}s_Q(v)
\]

각 영상의 쿼리 점수를 먼저 평균한 다음 최대 오답을 찾는다. 개별 쿼리의 최대 오답 점수를 평균하는 방식과 다르다.

\[
S^*=\arg\max_{S\subseteq C(q),\,|S|\leq2}
\left[M(\{q\}\cup S)-M(\{q\})-\lambda|S|\right]
\]

빈 집합의 개선량은 0이다. 유의한 개선이 없으면 추가 후보 0개를 선택하고, 거의 같은 결과에서는 후보 수가 적은 집합을 택한다. λ와 동률·개선 허용오차는 Train 내부 개발 분할에서 정한다. 개별 후보의 margin이 낮다고 쌍 평가 전에 제거하지 않는다. 서로 다른 오답 반응을 상쇄하는 쌍이 있을 수 있다.

| 선택 결과 | 집합 예시 | 해석 |
| --- | --- | --- |
| 유지 | 원문 | 유효하거나 도움이 되는 치환이 없음 |
| Object 선택 | 원문 + 특정 Object 위치를 바꾼 후보 | 해당 Object 치환이 기여 |
| Action 선택 | 원문 + 특정 Action 위치를 바꾼 후보 | 해당 Action 치환이 기여 |
| 두 후보 선택 | 원문 + 후보 A + 후보 B | 두 후보의 결합이 추가 기여 |

두 후보는 Object+Action뿐 아니라 Object+Object 또는 Action+Action일 수도 있다. **추가 쿼리 개수와 한 문장에서 바꾸는 단어 개수는 별개**다. 첫 실험은 추가 쿼리 하나에 한 위치만 바꿔 기여를 해석하기 쉽게 한다. 한 쿼리에서 Object와 Action을 함께 바꾸는 경우는 별도 비교군이다.

두 번째 후보에는 두 검사를 적용한다.

1. `원문+A+B`가 `원문+A`, `원문+B`보다 충분히 좋아야 한다. 후보 삭제로 결과가 거의 같으면 작은 집합을 선택한다.
2. `원문+A+B`를 `원문+A+A`, `원문+B+B`와 비교한다. 중복 집합은 후보 하나의 가중치가 2/3이 되는 대조군이므로, 단순 가중치 변화와 서로 다른 후보의 기여를 구분해서 해석한다.

이 margin 기준은 **학습 데이터의 정답 영상을 이용한 후보 선택 기준**이다. 정답을 모르는 실제 추론에서는 직접 사용할 수 없다. 추론용 선택기가 필요하면 Train에서 얻은 선택을 감독 신호로 사용하거나 정답 비의존 불확실성·점수 반응으로 예측하고, 정답 기반 선택의 상한과 따로 비교한다.

## 5. Holmes의 불확실성과 연결

원문 불확실성은 선택이 필요한 원문을 설명하는 신호로 사용한다. 높은 불확실성 자체를 무조건 증강할 이유로 삼지 않는다. 초기에는 낮은 불확실성 원문도 일부 분석하여 치환 효과와 불확실성의 관계를 확인한다.

핵심 가설은 **특정 Object/Action 치환이 오답 영상의 반응을 줄이거나 서로 보완하여, 같은 사건의 시각적 정합성을 유지한 채 검색 혼동을 줄일 수 있다**는 것이다. 치환 뒤 불확실성만 줄고 오답이 늘어나는 경우도 따로 보고한다.

유의어 쿼리는 정보가 중복되므로 독립 관측의 증거라고 가정하지 않는다. 초기 선택 실험에서는 similarity 평균을 사용하고, Dirichlet evidence 합산이나 기존 DST 결합의 효과는 중복 후보 대조군과 함께 별도로 확인한다. similarity 평균, 특징 평균, Dirichlet parameter 결합은 서로 다른 연산이다.

먼저 손실 함수와 evidence aggregation 구조를 유지한 채 선택된 추가 캡션의 효과를 측정한다. 원문별 총 학습 가중치 또는 샘플링 예산을 맞춰, 많은 후보를 가진 원문이 과도하게 학습되는 현상을 통제한다. 현재 Train loader는 영상의 모든 캡션을 가져오므로 TXT를 추가하는 것만으로는 이런 통제가 구현되지 않는다.

## 6. 효과를 입증할 비교 실험

| 비교군 | 검증할 내용 |
| --- | --- |
| 원문만 | 증강의 기준 성능 |
| 유효한 1순위 후보 전부 | 유효성 검사 후 전체 증강의 효과 |
| 선택 방식과 개수를 맞춘 무작위 후보 | 후보 개수와 선택 기준의 효과 분리 |
| Object만 선택 / Action만 선택 | 각 요소의 역할 |
| 최선의 개별 후보만 선택 | 후보 쌍 평가의 추가 효과 |
| 제안한 0·1·2개 최소 선택 | 필요에 따른 증강 효과 |
| 중복 후보 및 단순 가중치 변경 | 서로 다른 후보의 보완 효과 |
| 불확실성 신호 제거 / 추가 | Holmes 불확실성 신호의 기여 |

주 평가는 **선택된 Train 캡션으로 학습한 뒤 변경하지 않은 평가 원문으로 수행하는 single-query 검색**이다. 다중 쿼리 추론 점수가 올랐다는 사실만으로 학습 효과가 입증되지는 않는다. teacher margin 개선도 최종 학습 효과를 보장하지 않으므로 두 결과를 구분한다.

검색 R@1/5/10, 원문별 margin 변화, 선택 0·1·2개 비율, Object/Action·영역·어휘 빈도별 결과, 의미 오류율, 불확실성과 검색 오류의 관계를 보고한다. 불확실성 평가는 같은 오류 정의와 gallery에서 risk–coverage/AURC 등을 비교한다. 원문별 제거 실험으로 선택된 위치의 필요성을 확인한다.

같은 데이터 분할, 시작 checkpoint, query 학습량과 계산 예산을 기록하고 seed 2026을 기본으로 한다. teacher의 학습 영상과 선택 평가 영상은 Train 내부 영상 단위 분할 또는 교차 적합으로 구분하여 이미 학습한 정답에 대한 선택 편향을 점검한다. 현재 Train에는 과거 치환이 이미 적용된 캡션도 있으므로, 현재 Train을 원문으로 삼는 실험과 보관된 수정 전 원본을 사용하는 실험을 혼동하지 않는다.

## 7. Val 어휘 사용과 평가 범위

Val 표현을 후보 구성에 사용했다면 **평가 도메인의 텍스트 어휘를 제공받은 설정**으로 명시한다. 평가 도메인 정보 없이 Train만으로 후보를 만든 실험도 별도로 비교해야 일반적인 미관측 도메인 일반화 주장을 평가할 수 있다. Val의 정답 영상·검색 결과로 학습 후보를 골라 최종 성능을 보고하지 않는다. Val→Train 방향은 대응 어휘 분석 또는 별도 실험으로 두고, Val caption을 학습 positive로 편입하지 않는다.

2026-10-08 확인 시 `tvrval.caption.txt`와 `tvrtest.caption.txt`의 SHA-256은 모두 `ae9a60f6fc7581a3295e366d9a91c21b481d4411fb94b68422c09dc1751f3ef1`이다. 현재 두 파일을 독립된 개발·최종 평가 데이터로 취급할 수 없다. 최종 결과에는 후보 구성·설정 결정에 쓰지 않은 독립 평가 분할이 필요하다.

## 8. 구현 산출물과 현재 상태

구현 시 원문별 CSV에는 `source_caption_id`, 원문, 후보 ID와 치환 위치·표현, 유효성 판정과 사유, 원문 margin, 선택 집합 margin, 개선량, 개별 삭제 결과, 중복 후보 대비 개선량, 원문 불확실성, 선택 사유를 보존한다. 탈락·보류한 후보와 추가 후보 0개인 원문도 남겨 전체 데이터의 선택 경로를 볼 수 있게 한다. 최종 TXT는 원문을 모두 포함하고 선택된 쿼리만 추가한다.

현재 HDF5에는 rank1 후보의 366,444개 ID가 존재하는 것이 확인되었다. 다만 dataset별 문장 hash가 없어 ID 존재만으로 현재 CSV 문장에 해당하는 특징인지 입증할 수 없다. 특징 출처를 확인하고, Val 표면형으로 문장을 다시 만들면 해당 문장의 특징도 다시 추출해야 한다.

기존 `Holmes/Rewriter/evaluate.py`는 원문과 rewrite 한 개의 비교·결합을 지원한다. 연결 CSV 기반의 새 ID 매칭, 원문별 다후보·쌍 평가, 최소 집합 선택은 추가 구현이 필요하다. 기존 Val 점수 캐시는 Train 후보 선택 점수로 대신 사용할 수 없다.

큰 query×video 배열을 한 번에 저장하기보다 영상 특징을 재사용하고 query/video block별로 계산하는 방식을 우선 검토한다. hardest-negative 부분 집합만 쓰면 위 margin의 근사라는 점을 표시하고, 최종 후보 집합은 전체 고정 gallery에서 확인한다.

이 설계 문서 작성으로 기존 CSV·캡션·특징·모델 파일은 변경하지 않았다.
